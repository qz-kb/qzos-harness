# QZOS 员工 Host 适配

[English](README.md) | 中文

## 概述

为原生员工 Session 提供私有 QZOS 授权、知识检索、绑定能力和可选用量回执。

<a id="contract"></a>
## 契约

Web 组合与 ui-qzos 一起加载本私有插件。`apiUrl` 指定本机 QZOS API，`requestTimeoutMs` 限制单次业务请求。POST `/qzos/employees` 沿原连接认证，支持 authorize、logout、bind。令牌仅存内存；`qzos_employees` 存储域按原生 Session ID 持久保存不可改绑的账号、员工与后端归属。原生分叉在 `agent/created` 中沿 rc.5 Session 的 `parentSession` 继承绑定。回归测试调用真实 `SessionStore.fork`，并检查插件重载、员工暂停和退出后的继承授权。若上游版本移除分叉父级元数据，接入前须显式传递业务绑定；仅会话格式兼容不足以证明可升级。

未启用 `managedGateway` 的本地桌面或 Web Host 将配置的 `apiUrl` 注入为 `__QZOS_BUSINESS_API__`，使浏览器与 Host 使用同一业务后端；原生 `/api` 仍用于 DSH RPC。托管 Host 不向浏览器暴露内部 API 地址。

每个模型步骤前校验当前账号及员工可用性；有新用户输入时经授权检索知识，将允许的角色与片段通过 `agent/pre-step` 写入普通消息记录。DSH 保持执行与结果存储。未指定归属的本机预览中，账号切换取消上一账号的员工任务；Host 重启后需通过重新校验浏览器保存的业务会话或重新登录来恢复授权。移除时需同时移除本插件和对应浏览器接入。

部署网关管理登录时，同时设置 `managedGateway: true` 与 `ownerUserId`。Host 仅向私有浏览器 UI 注入指定用户 ID，不注入业务令牌；UI 使用网关 Cookie 与相对业务路径。网关须将认证请求绑定到该 Host，并在退出时撤销原生访问及实时连接。此配置本身不创建网关。

专用 Host 可配置 `ownerUserId`，值为所选后端返回的用户 ID。授权及绑定遇到不同的后端认证 ID 时返回 HTTP 403 与 `QZOS_HOST_ACCOUNT_MISMATCH`，不替换当前凭据。`qzos_host_owner` 存储域保存账号与完整 API URL；改动任一值或移除归属配置都会拒绝插件加载。已有其他账号的员工绑定也会拒绝加载。省略配置保留未指定归属的本机预览，不表示多用户部署。账号归属由部署配置指定，不接受浏览器声明或首次登录抢占。

每个指定用户使用全新的 Host 数据目录。不能直接给混合历史指定归属：本插件无法判断未绑定原生 Session 的所有者，迁移需要明确归属决策。原生认证、凭据、持久化、附件、存储、工作区及执行环境均须独立。仅分开 `DSH_HOME` 不能限制 shell 命令或绝对路径读取；须采用独立系统身份或不挂载其他用户数据的容器，将已认证用户仅路由至其 Host，并保护配置不被租户修改。原生 Host owner 凭据不可跨用户共享。单独业务退出仅撤销员工执行；托管网关另行撤销入口 Cookie、原生代理访问及实时连接。

<a id="optional-execution-adapter"></a>
## 可选执行适配

在本私有 Host 插件配置 `execution: { secretEnv: QZOS_DSH_BRIDGE_SECRET }`。共用签名秘密至少 32 字节，只放 Host／Server 环境变量。Server 执行 `php think dsh:migrate`，启用现有轨迹／反馈迁移，并用 `QZOS_DSH_MODEL_MAP` 将精确的 `provider/model` 映射到启用的子模型 ID。缺少映射或业务额度时拒绝绑定会话调用；员工保存的模型不覆盖工作窗口模型。适配默认关闭；关联知识库的员工必须启用。

`qzos_execution` v1 保存本轮元数据和按账号隔离的待结算回执，不保存令牌或签名秘密。模型回复与供应商实际用量先持久化，再结算。中断且无可信用量的调用保持未知；恢复只重提结算，不重调模型。Server 串行更新账号、快照单价、按调用 ID 去重，同一原生轮次更新一条回答记录。反馈关联这些服务端记录，不伪造接入前历史回答。标题／压缩辅助用量参与记账，但不替换回答。

按 Agent 注册的工具提供当前绑定能力、按表单校验后加载技能说明供窗口模型执行、调用允许的插件动作及查询已有结果。QZOS 重新检查当前绑定和授权。写入动作沿原生一次性确认；发送动作还确认服务端冻结的收件人与参数。结果未知只查询、不重发。业务令牌和确认秘密不进入模型。技能说明和插件结果增加普通上下文，可能引发额外模型步骤；不改变缓存结构。

`qzos_knowledge_search` 通过受信任检索适配器查询该员工绑定的知识库。模型可在做方案时用不同问题多次调用；结果是带知识库和来源标识的参考数据，不是指令。它复用自动检索的签名 `retrieve` 路径和轮次身份，员工知识权限与回执仍由 QZOS 裁定。仅在执行适配启用时注册。

未绑定员工的工作窗口获得 `qzos_knowledge_catalog` 和另一个接收显式 `knowledge_ids` 的 `qzos_knowledge_search`。目录列出账号可读的我的与共享知识库；检索用所选 ID 签名 `retrieve`，不依赖员工绑定。这是 `@知识库` 的 Host 侧，要求 Server 授权显式 ID 并返回相同来源行。

测试覆盖回执／账号隔离、缓存用量精确计算、工具确认／拒绝及未知结果。本机合成站已验证真实模型技能执行、插件读取／草稿／发送、取消／撤权、非零幂等结算和原生回答反馈。结果不代表生产部署、任意外部插件或 Host 多用户隔离。


<a id="model-experience"></a>
## 模型体验

### 员工知识

#### 模型看到什么

每轮新用户输入获得包含 `employeeId`、`name`、`role` 和授权 `sources` 的已记录上下文消息，不包含凭据及工作流配置。`qzos_knowledge_search` 以普通工具结果返回聚焦片段和来源字段；模型按提示引用并把它当作数据。

#### Token 影响

角色与检索片段增加输入 token；检索使用配置的 QZOS 向量模型。

#### KV Cache 影响

私有请求钩子仅应用员工温度，保留工作窗口 provider/model；不改变缓存布局。优化／重排参数传入现有 QZOS 检索 API。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- 每个 Host 仅支持一个活跃业务账号；企业部署通过独立 Host／容器隔离文件、历史和工具，共享本机预览不提供跨用户隔离。不恢复 PHP 聊天运行时，不支持员工外部工作流。可选私有执行适配回写实际用量及回答记录。检索失败拒绝执行。上下文增加输入 token，仅应用员工温度，不改变模型路由或缓存布局。

定向测试使用真实 HTTP 和存储域服务、合成上游响应，覆盖认证拒绝、绑定重载、逐轮检索、暂停员工、切换账号和退出。本机浏览器已验证 QZOS 检索与阿里云模型的真实知识回答、逐轮检索追问；还已验证 Host 重启后保存的业务会话重新校验、历史回读及不重新选择员工的追问检索。多个本机预览标签并存时可能出现恢复等待，重启时复用已有标签；结果沿 Product 原任务记录。

检索消息使用 `qzos-employee-context` 来源和 `snapshot` 形式；原生聊天隐藏此上下文，模型历史与 Session 记录保留，回答继续引用知识库编号。

### 开发备注

<details>
<summary>本机接入</summary>

实际验证结果沿 Product 原任务维护。

</details>

每条已授权片段保留白名单内的文件编号、名称、版本、片段编号及 QZOS 验证的解析坐标。记录到 Session 的上下文要求模型引用这些字段，不编造缺失位置。原生 Chat 继续隐藏上下文消息，并显示回答中的可读引用。

可选真实撤权测试 `tests/access-live.spec.ts` 使用 `QZOS_LIVE_ACCESS_DIR` 指定本机隔离合成夹具目录。目录需有 `member-account.json`、`member.json`、`access-state.json`（kb_id、employee、rule、body、url）和 `correction.pdf`，父目录为已有 owner `account.json`。测试独占夹具锁，真实登录并在同一绑定 Agent 内验证引用撤权／恢复、移除成员后的下一轮拒绝和原件下载拒绝；退出恢复合成成员与授予规则并释放 Host。仅对明确准备的可变合成夹具启用，不创建语言模型调用。

托管公开分享可配置 `publicVisitorOrigin`，仅允许无凭据、无路径的 HTTP(S) origin；该公开地址注入私有 UI，不使用容器内部 API 地址生成访客链接。真实双容器验证覆盖历史、文件、终端、重启持久化及退出撤权；企业后端／模型与签名回执在多容器组合下仍需部署配置验证。

执行日志在发送 begin 前持久化放行参数。放行响应丢失后，恢复复用同一调用身份；由于尚未进入供应商，按确定的零用量结清，不生成空回答。旧日志没有放行参数时仍按未知用量恢复。首次放行被明确拒绝时删除本地条目；结果不明的登记继续保留。只有服务端确认不存在已受理身份且当前准入被拒绝，才丢弃尚未进入供应商的登记；传输错误和身份冲突仍保留待恢复。服务端先核对已受理身份，再校验当前员工／模型是否允许新调用。

知识检索使用签名 `kb.dsh/retrieve`，同一账号、Session、轮次及问题使用稳定请求身份。员工设置、准入、多库全局选择和向量／优化／重排实际用量结算均由服务端负责。成功请求重试时重新校验来源权限后复用结果；结果不明的检索不会重调付费供应商。原无签名搜索测试回退已取消。参见[私有适配升级说明](../../../docs/upgrade-guide/v0.2.1-alpha.5/qzos-retrieval-receipts/guide.zh.md)。

检索传输失败时仅用同一请求标识续接一次；处理中响应保持当前轮次，以同一身份继续查询直到完成或取消；业务拒绝和主动取消不重试。再次传输失败结束本轮并提示恢复未成功，新提问使用新的请求标识。
